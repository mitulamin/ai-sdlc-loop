# scripts

| Script | What it does |
| --- | --- |
| `build-principles.py` | Regenerates `principles/*.md` from `data/principles.json`. `--check` fails if anything is stale. |
| `refresh-sources.py` | Compares each pinned SHA in `data/sources.json` with the upstream head. `--pin` and `--repin` move pins. |
| `build-agents.py` | Regenerates `agents/` (the coordinator and a producer and reviewer per phase) and `commands/` (the slash commands) from `data/skill-principle-map.json`, `data/taxonomy.json`, `data/principles.json`, `data/agent-contract.json` and `skills/`. Each lists its skills by ID, and every agent declares the required assumptions-and-open-questions output field with its register-request block. `--check` fails if anything is stale or an agent file lacks the field, the block or the instruction, and runs `register.py selftest`. |
| `build-site.py` | Regenerates the static site in `docs/` from `data/`, `guides/developer/` and `guides/use.md`, and the agents page from the `build-agents.py` model (which also reads `skills/`). Guide links to files under `docs/` become site-relative links; see [guides/README.md](../guides/README.md). It also fills in the marked regions of `guides/use.md` from `data/harnesses.json`. `--check` fails if anything is stale, those regions included. |
| `validate-data.py` | Validates every `data/*.json` against `data/schemas/`. Needs `pip install jsonschema`. |
| `check-skills.py` | Checks `skills/` against `data/principles.json` and `data/skill-principle-map.json`: one folder per principle with `SKILL.md` and `SOURCES.md`, matching front matter and aliases. Also fails if a file in `agents/` lacks the required output field, the register-request block or the instruction for agents that cannot write to the register. Standard library only. |
| `register.py` | `ingest` parses register-request blocks (`[TYPE: statement]` lines between `=== REGISTER REQUESTS ===` delimiters) and appends each statement verbatim to the shared surface register (JSON Lines, default `.ai-sdlc/register.jsonl`, format in `data/agent-contract.json`); `add` and `update` append single lines; `list --open` and `check` read it back; `selftest` checks that the parser round-trips every type. Standard library only. See [agents/README.md](../agents/README.md#the-shared-surface-register). |
| `check-links.py` | Checks internal links in `docs/` and markdown, offline. |
| `skillspector-scan.py` | Scans every folder in `skills/`, `agents/`, `commands/`, `template/` and a throwaway install for each harness with NVIDIA SkillSpector (`--no-llm`) and matches each finding against `.github/skillspector-exceptions.yaml` by rule, file, text and source line (with a per-file cap), failing on unexplained findings, incomplete coverage, files SkillSpector did not inspect, or stale/reasonless exceptions. Needs `skillspector==2.13.7` and `pyyaml`. |
| `skillspector-llm-scan.py` | The LLM-mode scan, and the one entry point for it in CI and locally: the same targets with SkillSpector's LLM analyzers on. Picks the provider by the key it finds: xAI when `XAI_API_KEY` is set (model chosen from its `XAI_MODELS` by what xAI lists for the key), else NVIDIA Build with `NVIDIA_INFERENCE_KEY` (model in its `NV_BUILD_MODEL`); `SKILLSPECTOR_PROVIDER` and `SKILLSPECTOR_MODEL` override. Scans targets in parallel (`SKILLSPECTOR_JOBS` or `--jobs`) and collects them into one record and exit code. `--record PATH` writes a record of every finding for a person to give a disposition; `--verify` checks the record is complete and made on the files in `HEAD`. It fails if the LLM stage did not really run (no key, rejected key, failed calls). Sends text to the provider. Required before every release: see [RELEASING.md](../RELEASING.md). |
| `skillspector_targets.py` | Not run directly. The scan targets and the exception matching that the two SkillSpector scripts share, and the pinned scanner version. |
| `new-project.sh` | `new-project.sh [--harness <name>] <target-dir> [profile]`. Copies the `template/` base, applies a profile (`solo` by default), installs the chosen harness's files with `install-harness.py`, and runs `git init`. With no harness, or `--harness none`, it installs no harness files. It writes only inside the target. `--help` lists the profiles and the harnesses. See the [Use page](../guides/use.md). |
| `install-harness.py` | `install-harness.py <project-dir> <harness>`. Writes this repo's skills, agents and commands into a project in the layout `data/harnesses.json` gives for the harness: the paths, file names, front matter, tool names and command prefix it expects. Links are rewritten to the installed copies or to this repo on GitHub at the installed commit. It puts each file under MIT unless it is adapted from a share-alike source (worked out from `data/licences.json`), adds a provenance comment stating the licence, writes licence notices into each skill's `SOURCES.md`, gives a share-alike skill its own `NOTICE.md` and licence copy, writes no project-wide notice, refuses to overwrite, and never writes outside the project. `--list` prints the harnesses; `--validate <harness>` checks one name. Standard library only. |
| `check-new-project.py` | Runs `new-project.sh` into temporary folders for every harness and for none, with `HOME` pointed at an empty folder. Fails if anything is written outside the target, a planned file is missing or extra, front matter or skill names are wrong, a provenance comment is missing, a file has the wrong licence, a notice or licence copy is outside a share-alike skill folder or the project root holds anything but the template `LICENSE`, a SOURCES.md lacks its copyright lines or a modified statement, a link does not resolve inside the project, or `--help` misses a profile or harness. Standard library only. |
| `bootstrap.sh` | `./scripts/bootstrap.sh`, run from inside your checkout. Needs git and python3 (it checks, never installs, and stops with a plain message if one is missing). Asks where to put the project (home, Documents if it exists, or the folder next to the checkout, with each full path shown) and what to call it, never inside the checkout, and asks again if the folder is in use. `AI_SDLC_BOOTSTRAP_LOCATION` (`home`, `documents`, `parent` or a full path) and `AI_SDLC_BOOTSTRAP_NAME` skip the questions. Then it runs `new-project.sh` for the solo profile and the Cursor harness, adds `START-HERE.md` and the always-on rule `.cursor/rules/ai-sdlc-bootstrap.mdc` from `template/bootstrap/`, puts a first-time note at the top of the project's `AGENTS.md`, and runs `git init` on `main` with no commit (the agent makes it). No GitHub, no accounts, no remote, and no Cursor or editor settings; it opens Cursor if its command is available. See the [Use page](../guides/use.md#bootstrap-for-cursor). |
| `check-bootstrap.py` | Runs `bootstrap.sh` from a copy of the checkout without `.git` (what downloading with curl gives), with `HOME` pointed at a fake folder and a fake `cursor` command. Fails if a refusal (missing git or python3, a place inside the checkout, a bad or used name, no answers) writes anything or is not plain; the questions do not list the places with full paths, hide or wrongly offer Documents, or fail to re-ask; the environment variables do not skip them; anything is written in the fake home other than the projects asked for; any editor, workspace, Cursor or model settings file is written; the Cursor files, licences or links are wrong (it reuses the `check-new-project.py` checks); the solo template or its `LICENSE` is wrong; `START-HERE.md`, the always-on rule or the first-time note at the top of the rule and `AGENTS.md` is missing or wrong; the project is not a git repository on `main` with no commits, nothing staged and no remote; or Cursor is not opened or the next steps are not printed. Standard library only. |

Python 3, git and bash. Everything is standard library only except `validate-data.py` (needs `jsonschema`) and `skillspector-scan.py` and `skillspector-llm-scan.py` (need `skillspector==2.13.7` and `pyyaml`). See [UPDATING.md](../UPDATING.md).
