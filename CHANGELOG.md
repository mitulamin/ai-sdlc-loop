- `RELEASING.md` and `scripts/skillspector-llm-scan.py`: the SkillSpector scan with the LLM analyzers on, run by the one script both in CI and locally. It picks the provider by the key it finds: xAI (`XAI_API_KEY`, `https://api.x.ai/v1` through SkillSpector's `openai_compatible` provider, with the first model from `XAI_MODELS` that xAI lists for the key, a fast non-reasoning Grok model first) when that is set, otherwise NVIDIA Build (`NVIDIA_INFERENCE_KEY`, SkillSpector's `nv_build` provider). `SKILLSPECTOR_PROVIDER` and `SKILLSPECTOR_MODEL` override the choice, and other SkillSpector providers such as `ollama` still work. With NVIDIA Build it pins its own model (`NV_BUILD_MODEL`, currently `nvidia/nemotron-3.5-super-vl-120b-a12b`, the quickest NVIDIA model that completed a trial scan), because SkillSpector 2.13.7's default for that provider, `z-ai/glm-5.3-flash`, is listed by NVIDIA Build but does not answer, which made every request time out. It refuses to count a run whose LLM stage did not really run, and checks the key and model before scanning (failing at once, with the reason, on a rejected key, a retired model or a model that does not answer). A target takes most of a minute whatever the model, so it scans targets in parallel (`SKILLSPECTOR_JOBS` or `--jobs`; the default depends on the provider's rate limit), scans a target whose calls failed again after an exponential backoff with jitter, collects every target into one record and exit code, and states the wall-clock time. It writes a record in which each finding gets a disposition (fixed, false positive, or accepted, with a reason). `--verify` checks the record is complete and was made on the files now in `HEAD`.

- Planning discipline in the Plan skills, from a comparison with an interactive brief-outlining agent (new wording, nothing copied). Locked decisions (1.2, 1.6): once the human has answered a decision, through a register question or the interview, downstream agents treat it as locked, raise a `[QUESTION: ...]` or `[BLOCKER: ...]` with evidence instead of overriding it, and the spec and plan reviewers flag a silent override. Exit test (1.2, 1.4 reviewers): every item is decided or parked with a reason and a revisit trigger, and no open choice affects behaviour, an interface, authorisation, the source of truth or rollout. Interview protocol (1.4): ground in the existing context, infer the decision areas from the goal, go one layer at a time ordered by coupling, and ask in one question format with the recommended option first. Decision sheet (1.2, 1.4): the interview outcome is recorded in the spec with the choice, who decided, why and the register id, and parked items carry a revisit trigger. Acceptance criteria (1.2, 1.7): numbered Given/When/Then, and each check names the criterion it proves. Anti-anchoring and no silent defaults (1.3, 1.4): weigh real alternatives, and declare any applied preference or default as `[ASSUMPTION: ...]`. `agents/`, `commands/` and `docs/` are regenerated, and the Using the agents and commands guide has a new Planning discipline section. The register-request block, the principles and the skill versions are unchanged (skills carry no version field).
- The assumptions and open questions field is written as a register-request block, one standard format for assumptions, open questions and blockers: `=== REGISTER REQUESTS ===`, then one `[TYPE: statement]` line each (`[ASSUMPTION: ...]`, `[QUESTION: ...]`, `[BLOCKER: ...]`), then `=== END REGISTER REQUESTS ===`, or `None.` between them. TYPE is any type in `register.types` in `data/agent-contract.json`, upper-cased, so adding a type is a data change only; `blocker` is a new register type. The block is identical for agents that can write the register (they run `scripts/register.py ingest` on their output) and agents that cannot (they emit it in their findings file and final message, and the coordinator writes it out verbatim). Every agent definition carries the instruction "Agents that cannot write to the register themselves must emit the register-request block in their transcript. Any coordinator invoking such an agent must take those register requests as-is and write them out verbatim.", and `scripts/build-agents.py --check` and `scripts/check-skills.py` fail if an agent lacks the field, the block or the instruction. `scripts/register.py ingest` parses the block and writes each statement verbatim (it fails on a malformed or missing block), and `scripts/register.py selftest`, run by `build-agents.py --check`, checks that every type round-trips. Skill 1.1 (surface assumptions) now tells its readers to use the block and carries the instruction; no other skill changed. `impact` and `urgency` are now optional on register entries, because a block line carries no rating: the coordinator rates entries with update lines and ranks blockers first. Entries gained an optional `via` field (agent or coordinator). Contract schema 1.1.0.

It is never a required relay: raw entries stay readable, and the human can answer in the register directly. Reviewers fail a producer output that lacks the `Assumptions and open questions` section, and the end-of-cycle report and `run-summary.md` carry the curated entries.
