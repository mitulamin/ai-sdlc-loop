# Changelog

All notable changes to this repo. The machine-readable version of the data changes is in [data/changelog.json](data/changelog.json). Process: [UPDATING.md](UPDATING.md).

## Unreleased

### Added

- Folder structure and placeholder READMEs for principles, skills, agents, commands, guides, docs, template and scripts.
- `README.md`, `UPDATING.md`, `CONTRIBUTING.md`, `NOTICE.md`.
- `data/principles.json`: 108 principles in 9 categories, imported from the initial research (run-1). No merges, no drops. The count is 103 after the dedupe listed under Changed.
- `data/sources.json`: the 41 source repos. Not pinned yet. Licences checked on 2026-11-26: 25 MIT, 6 Apache-2.0, 1 CC0-1.0, 1 CC-BY-SA-4.0, 3 with no licence file, and 5 described by their licence file (all rights reserved, CC BY-NC-ND 4.0, per-skill licences, Apache-2.0 text that GitHub reports as Other). Flags are in `ATTRIBUTIONS.md`.
- JSON schemas (version 1.0.0) for principles, sources and the data changelog in `data/schemas/`.
- `principles/<id>.md` for each principle, generated by `scripts/build-principles`.
- `scripts/refresh-sources.py` to compare pinned SHAs with upstream heads.
- `scripts/new-project.sh` and a minimal `template/`.
- `ATTRIBUTIONS.md`: links to all 41 source repos with their checked licences, and to works referenced but not sourced.

- Learning site in `docs/` (static, client-side JavaScript only, no build step to view, no trackers): a home page that walks the nine categories as a learning path, one page per category, one page per principle with sources linked through `data/sources.json`, a searchable, filterable and sortable table of all principles, a sources page, and the developer guide pages from `guides/developer/` (the guide is still a stub and the page says so). Generated by `scripts/build-site.py` from `data/` and `guides/developer/`, which also writes JSON copies to `docs/data/`.
- CI in `.github/workflows/ci.yml`: validates `data/*.json` against `data/schemas/` (`scripts/validate-data.py`), checks internal links in `docs/` and markdown (`scripts/check-links.py`), and fails if `principles/` or `docs/` are stale (`--check` on the two build scripts).

- Template profiles: `solo` (default), `small-team` and `large-org`, as small overlays in `template/profiles/`. One shared base, no copies. Solo skips gates and has no roles file. Small team adds a light review process and a short `ROLES.md`. Large org adds review gates, `ROLES.md` with owners and `.github/CODEOWNERS`.
- Base template now includes `CHANGELOG.md` and a basic pull request template, and `AGENTS.md` and `README.md` name the profile used.
- 103 skills in `skills/<id>-<slug>/`, one per principle, each with a `SKILL.md` and a `SOURCES.md`. Statements match `data/principles.json`; merged IDs are aliases on the survivor.
- `data/skill-principle-map.json`, `data/taxonomy.json`, `data/mapping.json`, `data/licences.json` and `data/scorecard.json`, each with a schema (version 1.0.0) in `data/schemas/`.
- `scripts/check-skills.py`, run in CI, which checks the skills against the principles and the skill data files.
- `CREDITS.md`: per-source credits with copyright lines and pins.
- Four MIT source repos for skill 7.12 in `data/sources.json` and `ATTRIBUTIONS.md` (`pr-evidence`, `pr-visuals`, `pr-screenshots`, `sideshot`), taking the count from 41 to 45. They are pinned.
- Skills page (`docs/skills.html`): the 103 skills in test run order, filterable by category, phase, test app and licence status, with each skill's slot, licence badge and scorecard score and verdict. It also shows the test apps and the nine phases from `data/taxonomy.json`. On narrow screens the table becomes stacked cards. The nav, the landing page and the learning path link to it, and a filtered view can be shared through the URL.
- Category pages now show the taxonomy: subgroups from `data/taxonomy.json` as headings, and under every principle its skill, phase, run slot, test app and licence badge. Principle pages show the skill's phase, slot, test app, licence status and scorecard row.
- `docs/data/` now also carries copies of `skill-principle-map.json`, `taxonomy.json` and `scorecard.json`, written by `scripts/build-site.py`.
- `.gitignore` for `__pycache__/` and `*.pyc`.
- `scripts/build-agents.py`, which generates `agents/` and `commands/` from `data/skill-principle-map.json`, `data/taxonomy.json`, `data/principles.json` and `skills/`: the coordinator, a producer and an adversarial reviewer for each of the nine phases (19 agents), and the seven commands `/plan`, `/design`, `/build`, `/verify`, `/review`, `/ship` and `/retro`. A phase loads the skills whose `phase` in the skill map is that phase, and every agent and command lists its skills by ID in its front matter. Producers get each skill's Do and Don't lists together; reviewers get only the reviewer checks and the Don't list. `--check` fails if anything is stale, and CI runs it.
- Agents page (`docs/agents.html`): the 19 agents and 7 commands with the skills each loads, linked from the nav. Generated by `scripts/build-site.py` from the same model as `scripts/build-agents.py`. The merged-ID redirect pages keep their old nav and are unchanged.
- `scripts/check-links.py` fails if `docs/`, `agents/` or `commands/` has no files to check, and reports how many it checked in each.
- Brand logo assets in `docs/assets/brand/` (favicon, header SVG logo, animated hero SVG logo, Open Graph / Twitter social card image, and README logo) with Open Graph and Twitter meta tags on generated pages (#13).
- `scripts/skillspector-scan.py` and `.github/skillspector-exceptions.yaml`, wired as the `skillspector` job in `.github/workflows/ci.yml`: runs NVIDIA SkillSpector (`2.13.7`, `--no-llm`) against every skill folder in `skills/`, failing on unexplained findings, incomplete coverage, or stale/reasonless exceptions. Exceptions are matched per finding, not per file: each names the rule, file, matched text and full source line (`line`) and may explain at most `max_per_file` findings per file (default 1), so a second hit with the same text in a file fails.

### Changed

- Merged five duplicate principles, taking the count from 108 to 103 (dedupe pass by Rex). The old ID stays as an alias on the survivor, no other principle was renumbered, and the old principle pages redirect to the survivor. Details and reasons are in [MERGES.md](MERGES.md).
  - 4.4 into 4.1 (one test per cycle is a rule within red-green TDD).
  - 4.5 into 5.3 (the reproducing test is the first step of 5.3).
  - 9.4 into 5.1 (same technique, same source).
  - 5.6 into 5.10 (same rule).
  - 2.11 into 6.3 (same rule).
- Sharpened the wording of eight overlapping pairs that stay separate, and added a "how it differs" note to each principle: 2.14/3.5, 7.6/7.10, 7.1/8.7, 4.9/7.12, 3.14/5.4, 8.5/9.9, 8.1/8.3, 2.5/3.1.
- `data/schemas/principles.schema.json` is now version 1.1.0, with optional `aliases` and `distinct_from` fields. To migrate, set `schema_version` to `"1.1.0"` in `data/principles.json`; existing entries stay valid.
- Skills now exist, so the README status and table rows, `skills/README.md`, `data/README.md`, `scripts/README.md`, the `ATTRIBUTIONS.md` intro and counts, and the CONTRIBUTING "Add a skill" section no longer say skills are still to come. `principles/<id>.md` now links each principle's skill.
- Site principle pages now link the principle's skill instead of saying it is not written yet. The landing page reports 41 repos reviewed and 45 sources cited, the sources page reports both, and the learning path reports the 41 reviewed. Generated by `scripts/build-site.py`.
- The principles table filters now use the same data-attribute filter script as the skills table, so both read their state from the URL.
- README `scripts/` row lists every script (it was missing `build-site.py`, `validate-data.py`, `check-skills.py` and `check-links.py`).
- `UPDATING.md` and `CONTRIBUTING.md`: a merged principle now leaves the list and lives on as an alias, instead of staying with a `merged` status.

- The site homepage is now a landing page (`docs/index.html`) that explains what the project is, who it is for, how the loop works, what you can do on the site and how to start a project from `template/`. Counts on it come from the data. The learning path moved to `docs/path.html`, and the nav and breadcrumbs on every generated page now start at Home. Generated by `scripts/build-site.py`.
- Renamed `scripts/build-principles` to `scripts/build-principles.py` so every script has an extension that matches its language. References in the README, CONTRIBUTING, UPDATING, the pull request template, the CI workflow and the generated `principles/` files are updated.
- The learning site's visible name is "AI SDLC Loop" (page titles, header and footer). The repo name and URLs are unchanged.
- `run_order` in `data/taxonomy.json` now describes the real slot order: Agent operations first, then test apps A, B and C, with Learn on the first run (slots 33-43). No slot was renumbered. The copy in `docs/data/` is regenerated.
- The skills page footer says it is generated from the principles, skill map, taxonomy and scorecard data, and links all four files.
- `agents/README.md` and `commands/README.md` are now generated by `scripts/build-agents.py`. The README, `scripts/README.md`, `docs/README.md`, `UPDATING.md` and the CONTRIBUTING "Add a skill" section say so.
- Pinned all 45 source repos in `data/sources.json` to the commit they were reviewed at (`pin_source: review-record` on all 45, none on `github-head`): 36 to the review commits recorded in `data/licences.json`, and 9 to the review commits supplied with the Step 4 review (`PatrickJS/awesome-cursorrules`, `VoltAgent/awesome-agent-skills`, `VoltAgent/awesome-claude-code-subagents`, `affaan-m/ECC`, `microsoft/skills` and `travisvn/awesome-claude-skills` already sat on that commit, and `anthropics/claude-code`, `hesreallyhim/awesome-claude-code` and `sickn33/agentic-awesome-skills` were moved to it from the default-branch HEAD of 2026-11-26). Extended `data/schemas/sources.schema.json` additively with optional `commit_date` and `pin_source` fields, and updated `docs/sources.html` (commit date next to the SHA, pin date labelled "pinned") and `ATTRIBUTIONS.md` to display the pins. `scripts/refresh-sources.py` now records `commit_date` on a re-pin.
- Follow-ups from the Step 3 review: pointed `scripts/build-agents.py` (`agents/coordinator.md`) and the 103 `skills/*/SKILL.md` test plans from `scorecard.csv` to `data/scorecard.json`, fixed the count in skill `8.5` from 108 to 103, added a `tools` list to the 9 adversarial reviewer agents: `Read`, `Grep`, `Glob`, `Bash`, `Write` for build, verify, debug, secure and review-and-ship, which must run checks and show the command and output (4.9), and `Read`, `Grep`, `Glob`, `Write` for harness, plan, design and learn. This is a prompt rule (reviewers write only the findings file), not enforcement: Cursor subagents ignore `tools:` and use read-only mode, and real enforcement needs hooks. Write can still overwrite code, set `SITE_ORIGIN` in `scripts/build-site.py` so `og:image`, `twitter:image` and `og:url` are absolute URLs, and listed `docs/assets/brand/` as hand-written in `docs/README.md`.

- `scripts/new-project.sh` takes a profile argument (`scripts/new-project.sh <target-dir> [profile]`, default `solo`), shows usage with `--help` or on bad input, and still refuses a target that is not empty. It copies the base, then applies the profile.
