# docs

The static website (GitHub Pages): a landing page that explains the project, a learning path through the 103 principles, a page per category, a page per principle (and one for each of the 5 merged IDs, which opens its survivor), a searchable and sortable principles table with phase, test app, slot and licence status, a skills page in run order, a sources and licences page with the link-only sources separated, and the developer guide pages. Client-side JavaScript only, no build step to view it, no external scripts or trackers. Open `docs/index.html` in a browser to try it. The landing page is `index.html` and the learning path is `path.html`.

## Generated and hand-written

Everything is generated by `scripts/build-site.py` from `data/principles.json`, `data/skill-principle-map.json`, `data/mapping.json`, `data/licences.json`, `data/sources.json`, `scorecard.csv` and `guides/developer/*.md`, except these hand-written files:

- `assets/style.css`
- `assets/site.js`
- `.nojekyll`
- this `README.md`

Do not edit generated files, they are overwritten. The build joins those data files and stops with a message if they disagree (IDs, counts, slot, app, phase, licence status). `docs/data/` holds copies of the JSON files and `scorecard.csv` for readers. After changing anything in `data/`, `scorecard.csv` or `guides/developer/`, run:

```
scripts/build-site.py
```

CI runs `scripts/build-site.py --check` and fails if the output is stale. The landing page is built by `Site.landing_page` in the script. The learning-path text for each category lives in `PATH_TEXT` at the top of the script.
