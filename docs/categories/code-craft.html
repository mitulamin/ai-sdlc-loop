Stage 3: Code craft

Write the smallest change that does the job, in the style already there.

This is the day-to-day work of building. The theme is restraint: no speculative code, no drive-by edits.

14 principles

  1. 3.1 Write the minimum code that solves the problem; nothing speculative
  2. 3.2 Make surgical changes: every changed line traces to the request
  3. 3.3 Match the existing style and conventions
  4. 3.4 Keep functions small and at one level of abstraction
  5. 3.5 Keep parameters few; model the concept instead of passing flags
  6. 3.6 Separate commands from queries; no hidden side effects
  7. 3.7 Comments explain why, never narrate what
  8. 3.8 Prefer clarity over cleverness
  9. 3.9 Understand why code exists before removing it (Chesterton's fence)
  10. 3.10 Refactor in small behaviour-preserving steps, kept separate from feature changes
  11. 3.11 Name the code smell and apply its standard remedy
  12. 3.12 Use what's installed; never add a dependency for a few lines
  13. 3.13 Never cut boundary validation, data-loss handling or security to save code
  14. 3.14 One thing at a time, in vertical slices, keeping the build green
