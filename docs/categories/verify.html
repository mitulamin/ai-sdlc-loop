Stage 4: Verify (testing)

Prove the code does what you said it would.

Tests are how an agent, or you, can tell working from broken without guessing. These principles cover what to test and how to keep tests honest.

10 principles

  1. 4.1 Write a failing test first and watch it fail
  2. 4.2 Test behaviour through public interfaces, not implementation details
  3. 4.3 No tautological tests that recompute the expected value the way the code does
  4. 4.4 One seam, one test, one minimal implementation per cycle; never write all tests first
  5. 4.5 Start every bug fix with a test that reproduces it
  6. 4.6 Review suites for mock abuse, brittleness and coverage illusions; coverage is not quality
  7. 4.7 Balance the test pyramid by size and cost
  8. 4.8 Treat tests as production code: readable and deterministic
  9. 4.9 No completion claims without fresh verification evidence
  10. 4.10 Mark anything you couldn't test as untested, with the reason; never skip silently
