Stage 4: Verify (testing)

Prove the code does what you said it would.

Tests are how an agent, or you, can tell working from broken without guessing. These principles cover what to test and how to keep tests honest.

The 8 skills here run in these phases: Verify (8). See them in run order.

8 principles

  1. 4.1
    Write one failing test first and watch it fail, then write the minimal code to pass; one seam per cycle, never all tests up front.

    Skill red-green-tdd · Verify phase · run slot 26 · App A: CLI tool, greenfield Clean

  2. 4.2
    Test behaviour through public interfaces, not implementation details

    Skill test-behaviour-via-public-interfaces · Verify phase · run slot 27 · App A: CLI tool, greenfield Clean

  3. 4.3
    No tautological tests that recompute the expected value the way the code does

    Skill no-tautological-tests · Verify phase · run slot 28 · App A: CLI tool, greenfield Clean

  4. 4.6
    Review suites for mock abuse, brittleness and coverage illusions; coverage is not quality

    Skill review-suites-for-mock-abuse · Verify phase · run slot 98 · App C: Brownfield fix and refactor Clean

  5. 4.7
    Balance the test pyramid by size and cost

    Skill balanced-test-pyramid · Verify phase · run slot 65 · App B: Small CRUD web app with auth, greenfield Clean

  6. 4.8
    Treat tests as production code: readable and deterministic

    Skill tests-as-production-code · Verify phase · run slot 29 · App A: CLI tool, greenfield Clean

  7. 4.9
    Do not claim the work is done until you have just run the verification and read its output

    Skill evidence-before-completion · Verify phase · run slot 30 · App A: CLI tool, greenfield Rewritten

  8. 4.10
    Mark anything you couldn't test as untested, with the reason; never skip silently

    Skill mark-untested-with-reason · Verify phase · run slot 31 · App A: CLI tool, greenfield Rewritten
