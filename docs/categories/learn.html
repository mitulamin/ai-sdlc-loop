Stage 9: Learn

Turn what went wrong into a better loop.

The loop gets better only if mistakes change the rules. This closes the cycle and feeds back into stage one of the next project.

11 principles

  1. 9.1 When the reviewer missed a mistake, give the reviewer a new rule; if the mistake is mechanical, build a lint, hook or CI check instead
  2. 9.2 Enforce standards at review, not by loading them into the implementer's context
  3. 9.3 Remove or clarify rules that don't change behaviour
  4. 9.5 Ask what conditions allowed the failure, not who caused it (blameless, 5 whys)
  5. 9.6 Group failures by the mechanism behind them, not by error text
  6. 9.7 Before hardening a skill, reproduce the failure as a baseline scenario and record the agent's excuses; then close the loophole and re-test
  7. 9.8 Keep each learned edit small, to one surface, and keep behaviour that already passes
  8. 9.9 Accept a rule change only if it measurably helps on held-out cases
  9. 9.10 A human approves each learned change before it goes live
  10. 9.11 Capture corrections as they happen; process them later in a batch
  11. 9.12 Keep a record of every accepted and rejected edit
