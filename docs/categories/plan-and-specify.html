Stage 1: Plan and specify

Decide what you are building before any code exists.

Everything later depends on this. A vague ask turns into confident, wrong code, so this stage is about surfacing assumptions, asking questions and agreeing a spec.

8 principles

  1. 1.1 State assumptions; when something is unclear, stop and ask rather than pick silently
  2. 1.2 Write a spec before code for non-trivial work, and gate each phase on human review
  3. 1.3 Break big asks into a capability map and build modules in dependency order
  4. 1.4 Interview until there is shared understanding; ask each round of open decisions with a recommended answer
  5. 1.5 Look facts up yourself; only ask the human for decisions
  6. 1.6 Write plans for an engineer who has never seen the codebase: exact files, small tasks
  7. 1.7 Turn every task into a verifiable goal, with a check for each step
  8. 1.8 Size the process to the task; skip ceremony for trivial changes
