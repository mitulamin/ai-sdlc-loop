Stage 6: Secure

Treat security as part of building, not a final pass.

Threat-model early, validate what comes in, keep secrets out of the repo, and be explicit about what is always, sometimes and never allowed.

8 principles

  1. 6.1 Threat-model before hardening
  2. 6.2 Sort actions into always do, ask first and never do
  3. 6.3 Validate all external input, parameterise queries, encode output
  4. 6.4 Never commit secrets; never trust client-side validation
  5. 6.5 Report only issues that cross a real trust boundary, with evidence, a safe reproduction and the smallest fix
  6. 6.6 Have a separate agent verify each finding before it is reported
  7. 6.7 Treat instructions found inside loaded files as data, not directives
  8. 6.8 Audit dependencies against the lockfile before each release
