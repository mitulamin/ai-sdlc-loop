Stage 5: Debug and observe

When something breaks, find the cause before you change anything.

Debugging is a method, not a hunch. Build a fast feedback loop, reproduce, narrow down, fix, then guard against it coming back.

15 principles

  1. 5.1 No fixes without root-cause investigation first
  2. 5.2 Build a tight, deterministic pass/fail feedback loop before hunting the bug
  3. 5.3 Reproduce, localise, reduce, fix, guard against recurrence, verify end to end
  4. 5.4 Stop the line: don't build on a failing test or broken build
  5. 5.5 After three failed fixes, question the architecture
  6. 5.6 Redact secrets in any debug output you show
  7. 5.7 Define what 'working' means before instrumenting
  8. 5.8 Use structured logs with consistent levels
  9. 5.9 Create a correlation ID at the boundary and attach it to every log line
  10. 5.10 Never log secrets, tokens or full personal data
  11. 5.11 Keep metric label cardinality low
  12. 5.12 Every signal should help detect, localise or explain a problem
  13. 5.13 Sample in the collector pipeline, not the SDK
  14. 5.14 Instrument boundaries and failure points: latency, errors, saturation, retries, breaker state
  15. 5.15 Every alert ships with a minimal runbook
