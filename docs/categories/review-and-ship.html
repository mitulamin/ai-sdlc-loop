Stage 7: Review and ship

Get a second pair of eyes on the work, then release it safely.

Review is where mistakes are caught cheaply. Shipping is where they get expensive. These principles cover both.

The skills here run in these phases: Review & ship. See them in run order.

Principles

  1. 7.1
    Review the work at the end of each phase, using a separate reviewer subagent that did not write it

    Skill separate-reviewer-early-and-often · Review & ship phase · run slot 32 · App A: CLI tool, greenfield Clean

  2. 7.2
    Review on five axes: correctness, readability, architecture, security, performance

    Skill five-axis-review · Review & ship phase · run slot 82 · App B: Small CRUD web app with auth, greenfield Clean

  3. 7.3
    Approve when a change improves code health, not when it is perfect

    Skill approve-on-improved-health · Review & ship phase · run slot 83 · App B: Small CRUD web app with auth, greenfield Clean

  4. 7.4
    Review against both the standards and the spec, in parallel

    Skill review-against-standards-and-spec · Review & ship phase · run slot 84 · App B: Small CRUD web app with auth, greenfield Clean

  5. 7.5
    Rank findings by severity (P0-P3)

    Skill severity-ranked-findings · Review & ship phase · run slot 85 · App B: Small CRUD web app with auth, greenfield Rewritten

  6. 7.6
    Keep each change, meaning one commit or pull request, small and about one thing, so it is easy to review and to revert

    Skill small-focused-changes · Review & ship phase · run slot 86 · App B: Small CRUD web app with auth, greenfield Clean

  7. 7.7
    One worktree and branch per task and per agent

    Skill worktree-per-task · Review & ship phase · run slot 87 · App B: Small CRUD web app with auth, greenfield Rewritten

  8. 7.8
    Never commit to main or force-push

    Skill protect-main · Review & ship phase · run slot 88 · App B: Small CRUD web app with auth, greenfield Rewritten

  9. 7.9
    No quality gate is skippable: fix the code, don't disable the check

    Skill no-skippable-gates · Review & ship phase · run slot 89 · App B: Small CRUD web app with auth, greenfield Clean

  10. 7.10
    Shift checks left and release in small, frequent batches, so problems show up early and each release carries little risk

    Skill shift-left-ci · Review & ship phase · run slot 90 · App B: Small CRUD web app with auth, greenfield Rewritten

  11. 7.11
    Give feature flags a lifecycle that ends in removing them

    Skill feature-flag-lifecycle · Review & ship phase · run slot 91 · App B: Small CRUD web app with auth, greenfield Clean

  12. 7.12
    Attach before-and-after proof to each change you ship, such as test output, screenshots or measurements, so a reviewer can see the effect

    Skill before-and-after-proof · Review & ship phase · run slot 92 · App B: Small CRUD web app with auth, greenfield Rebuilt
