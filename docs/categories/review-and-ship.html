Stage 7: Review and ship

Get a second pair of eyes on the work, then release it safely.

Review is where mistakes are caught cheaply. Shipping is where they get expensive. These principles cover both.

12 principles

  1. 7.1 Review early and often, using a separate reviewer subagent
  2. 7.2 Review on five axes: correctness, readability, architecture, security, performance
  3. 7.3 Approve when a change improves code health, not when it is perfect
  4. 7.4 Review against both the standards and the spec, in parallel
  5. 7.5 Rank findings by severity (P0-P3)
  6. 7.6 Keep each change small and about one thing
  7. 7.7 One worktree and branch per task and per agent
  8. 7.8 Never commit to main or force-push
  9. 7.9 No quality gate is skippable: fix the code, don't disable the check
  10. 7.10 Shift left, and ship in small, frequent batches
  11. 7.11 Give feature flags a lifecycle that ends in removing them
  12. 7.12 Ship with before-and-after proof
