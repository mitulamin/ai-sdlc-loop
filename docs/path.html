A learning path through 103 software principles

These principles were distilled from 41 public repos of agent skills, sub-agents and commands. They are the base of a loop that builds software with agents and learns from each project. Work through the nine stages in order, or jump straight to the one you need.

The nine stages

The order follows a project from idea to retrospective. Stage 9 feeds back into stage 1 of the next project.

  1. 1

    Plan and specify 8 principles

    Decide what you are building before any code exists.

    Everything later depends on this. A vague ask turns into confident, wrong code, so this stage is about surfacing assumptions, asking questions and agreeing a spec.

    Start with 1.1: State assumptions; when something is unclear, stop and ask rather than pick silently

  2. 2

    Design and architecture 18 principles

    Shape the code so it is easy to change and easy to test.

    Once you know what to build, decide where the boundaries go. Good seams and small interfaces make the next three stages cheaper.

    Start with 2.1: Design deep modules: a lot of behaviour behind a small interface

  3. 3

    Code craft 14 principles

    Write the smallest change that does the job, in the style already there.

    This is the day-to-day work of building. The theme is restraint: no speculative code, no drive-by edits.

    Start with 3.1: Write the minimum code that solves the problem; nothing speculative

  4. 4

    Verify 8 principles

    Prove the code does what you said it would.

    Tests are how an agent, or you, can tell working from broken without guessing. These principles cover what to test and how to keep tests honest.

    Start with 4.1: Write one failing test first and watch it fail, then write the minimal code to pass; one seam per cycle, never all tests up front.

  5. 5

    Debug and observe 14 principles

    When something breaks, find the cause before you change anything.

    Debugging is a method, not a hunch. Build a fast feedback loop, reproduce, narrow down, fix, then guard against it coming back.

    Start with 5.1: No fixes without root-cause investigation first: trace back to the original trigger, not where the symptom showed up.

  6. 6

    Secure 8 principles

    Treat security as part of building, not a final pass.

    Threat-model early, validate what comes in, keep secrets out of the repo, and be explicit about what is always, sometimes and never allowed.

    Start with 6.1: Threat-model before hardening

  7. 7

    Review and ship 12 principles

    Get a second pair of eyes on the work, then release it safely.

    Review is where mistakes are caught cheaply. Shipping is where they get expensive. These principles cover both.

    Start with 7.1: Review early and often, using a separate reviewer subagent

  8. 8

    Agent operations 10 principles

    Run the agents themselves well.

    Context is limited and expensive. This stage is about what an agent sees, how skills are loaded, and how work is split between a coordinator and the agents it starts.

    Start with 8.1: Load only the context the task needs, such as the relevant spec section

  9. 9

    Learn 11 principles

    Turn what went wrong into a better loop.

    The loop gets better only if mistakes change the rules. This closes the cycle and feeds back into stage one of the next project.

    Start with 9.1: When the reviewer missed a mistake, give the reviewer a new rule; if the mistake is mechanical, build a lint, hook or CI check instead
