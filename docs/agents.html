The agents and commands

The human talks only to the coordinator. For each phase it starts a producer and then a strictly adversarial reviewer, each in a fresh context. Producers load each skill's Do and Don't lists together, its related practices and its Self-check, and end their report with a principle self-check table. Reviewers load only each skill's adversarial reviewer checks and the Don't list, and test that table as a claim. A phase loads the skills whose phase in data/skill-principle-map.json is that phase. The agent and command files are generated by scripts/build-agents.py.

Commands

The human gives a command to the coordinator, which runs the loop for each phase on its own and reports at the end of the cycle. The Harness phase has no command: the coordinator runs it.

Assumptions and open questions

Every agent has one required output field, assumptions_and_open_questions: its output ends with a section headed “Assumptions and open questions”. It is required. An explicit None. is allowed when there are none; leaving the section out is not. In that section the agent writes a register-request block, in the same format whether or not it can write to the register itself:

=== REGISTER REQUESTS ===
[ASSUMPTION: <one-line statement>]
[QUESTION: <one-line statement>]
[BLOCKER: <one-line statement>]
=== END REGISTER REQUESTS ===

One line per entry: the type in capitals, a colon, a space and a one-line statement, all inside square brackets. TYPE is any type in register.types, upper-cased, so adding a type to register.types is a data change only. Put None. alone between the delimiters when there are no entries. The block is identical whoever writes the register. Whoever writes it out copies each statement exactly: no summarising, merging, rewording, reordering or dropping.

  • ASSUMPTION: something you decided without being able to confirm it, and carried on with.
  • QUESTION: something you could not settle yourself and want answered, ideally with your recommended answer in the statement.
  • BLOCKER: something that stops you finishing, or finishing correctly, until it is resolved.

Agents that cannot write to the register themselves must emit the register-request block in their transcript. Any coordinator invoking such an agent must take those register requests as-is and write them out verbatim. Agents that can write to the register run scripts/register.py ingest on their own output. The agents with no shell (harness-reviewer, plan-reviewer, design-reviewer, learn-reviewer) emit the block in their findings file and in their final message, and the coordinator writes it out verbatim. scripts/build-agents.py --check and scripts/check-skills.py fail if an agent lacks the field, the block or the instruction.

The shared surface register

The register is a plain file the coordinator treats as its inbox: it pulls the register, rates, curates and de-dupes it, ranks what is open (blockers first), batches it for the human, and records what it surfaced and what the human answered. It is never a required relay, because every raw entry stays readable, and answerable, by the human directly. Commands that start a phase take --register <path>; the default is .ai-sdlc/register.jsonl. The format is JSON Lines: one JSON object per line, UTF-8, append-only. Never edit or delete a line; a change of state is a new line.

EventWhat it isFields
declareAn agent declares an assumption it made, a question it could not answer, or a blocker. The text is the statement from its register-request block, verbatim.
id, event, ts, agent, phase, type, text, status, impact, urgency, recommendation, via
updateThe coordinator or the human changes the state of an earlier entry, or rates it.
id, event, ts, agent, phase, ref, status, note, answer, by, impact, urgency

An entry has a type (assumption, question, blocker), the statement verbatim, and a status (open, surfaced, answered, dismissed, duplicate); impact and urgency (low, medium, high) are added when the coordinator rates it. Field meanings, an example and the helper script are in agents/README.md; the data is data/agent-contract.json.
