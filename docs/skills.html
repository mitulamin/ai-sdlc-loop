The skills, in test run order

There is one amalgamated skill per principle. Each has a phase, a test app and a slot. The slot is its place in the run order, and the test app is the project it is exercised on. Skills are scored in data/scorecard.json; a skill that has not been run yet shows “not run”, and its status says whether it is still a draft. Licence status says whether every source could be adapted (clean), or whether link-only sources were moved to Further reading (rewritten, rebuilt).

Phases

Each phase is a producer and an adversarial reviewer. A category can span more than one phase.

  1. 1. Harness

    Role: harness engineer

    Producer harness-producer, reviewer harness-reviewer. Commands: none.

    Categories: Agent operations

  2. 2. Plan

    Role: planner

    Producer plan-producer, reviewer plan-reviewer. Commands: /plan.

    Categories: Plan and specify

  3. 3. Design

    Role: architect

    Producer design-producer, reviewer design-reviewer. Commands: /design.

    Categories: Design and architecture

  4. 4. Build

    Role: implementer

    Producer build-producer, reviewer build-reviewer. Commands: /build.

    Categories: Code craft, Debug and observe

  5. 5. Verify

    Role: tester

    Producer verify-producer, reviewer verify-reviewer. Commands: /verify.

    Categories: Verify (testing)

  6. 6. Debug

    Role: debugger

    Producer debug-producer, reviewer debug-reviewer. Commands: /verify.

    Categories: Debug and observe

  7. 7. Secure

    Role: security engineer

    Producer secure-producer, reviewer secure-reviewer. Commands: /review.

    Categories: Debug and observe, Secure

  8. 8. Review & ship

    Role: release manager

    Producer review-and-ship-producer, reviewer review-and-ship-reviewer. Commands: /review, /ship.

    Categories: Debug and observe, Review and ship

  9. 9. Learn

    Role: learner

    Producer learn-producer, reviewer learn-reviewer. Commands: /retro.

    Categories: Learn
